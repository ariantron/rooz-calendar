# Contributing

## Getting set up

```bash
pnpm install
pnpm test        # calendar-core unit tests
pnpm dev         # the site; /demo is the playground for visual checks
```

## The one rule

**The grid must be computed natively in the active calendar system.** Nothing may compute a
layout in Gregorian and relabel it. If you find yourself converting to a `Date`, doing month
arithmetic on it and converting back, stop — ask the `CalendarSystem` instead. That principle
is the entire reason this library exists rather than a wrapper around FullCalendar.

Concretely:

- Date arithmetic goes through `system.addDays` / `addMonths` / `toDayNumber`, never through
  millisecond maths on a `Date`.
- Month lengths come from `system.daysInMonth`, never from a hardcoded table outside a system
  implementation.
- Week alignment comes from `weekStartsOn`, never from `Date.prototype.getDay()` assumptions.
- Nothing outside `systems/jalali.ts` may import `jalali-moment`.

## Tests

`packages/calendar-core` is where the risk lives, and it is the only package with a required
test suite. Any change to conversion, month lengths, leap rules or grid alignment needs a test
with a **hand-verified** expected value — a published Nowruz date, a known historical date, a
month length you can check against a printed calendar. Do not derive an expectation by running
the code you are testing.

Useful anchors:

- Nowruz 1403 = 2024-03-20, Nowruz 1405 = 2026-03-21 (a Saturday, so Farvardin 1405 starts
  flush in column 0).
- 22 Bahman 1357 = 1979-02-11.
- Jalali leap years near now: 1395, 1399, 1403, 1408, 1412.

## The generated API snapshot

`apps/web/src/generated/api.json` is generated from the TypeScript sources and **committed on
purpose**. It is regenerated by `pnpm build:site`, so it cannot go stale — and keeping it in
the repo means every pull request's diff shows exactly what changed in the public API. That is
the cheapest possible semver review: if the diff removes or renames anything, the change is
breaking. Regenerate it with `pnpm --filter @rooz-calendar/web generate:api` when you change an export.

## Before opening a PR

```bash
pnpm test
pnpm typecheck
pnpm build
```

CI runs the calendar-core suite on every pull request. If your change touches packaging, run
`pnpm smoke` too — it packs the libraries and installs them into a throwaway app, which is the
only thing that catches `files`/`exports` mistakes.
